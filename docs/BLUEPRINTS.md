# Blueprints

Stockit follows the shared blueprints in https://github.com/gadominas/app-blueprints from its first version.
The script's `BLUEPRINTS` block is the source of truth; this table mirrors it and adds deviations.

| Blueprint | Version | Since app version | Deviations |

| [stability-patterns](https://github.com/gadominas/app-blueprints/blob/stability-patterns-v1.0.1/blueprints/stability-patterns.md) | 1.0.1 | 1.27.2 | Storage, updates and the installer touch iCloud only when the script lives in iCloud Drive; checked with `no-icloud-check.js` (app, widget, installer) |
| [in-app-updates](https://github.com/gadominas/app-blueprints/blob/in-app-updates-v1.1.0/blueprints/in-app-updates.md) | 1.1.0 | 1.27.2 | Settings › Updates keeps **Check for updates now** (`checkForUpdate(true)`, which skips the snooze); in a native shell it is hidden with the switch |
| [settings](https://github.com/gadominas/app-blueprints/blob/settings-v1.1.2/blueprints/settings.md) | 1.1.2 | 1.20.1 | Each palette adds two Stockit colours, `up` and `down` (CSS `--up`, `--down`), for gains and losses; every other colour is a shared token. Settings load at the top of the script (no `loadSettings()`), before every branch, as in BlogPulse. One extra secret, an optional Finnhub key, follows Step 7 (own Keychain entry `STOCKIT_FINNHUB_KEY`, native secure prompt, the page sees only its last four characters); Section cards (1.1.0) are built by `cardSections()` right after each render, giving the same markup as Step 5 without rewriting every section's code; the card CSS is scoped under `#cfgsheet` |

| [usage-analytics](https://github.com/gadominas/app-blueprints/blob/usage-analytics-v1.1.0/blueprints/usage-analytics.md) | 1.1.0 | 1.16.0 | The question card is drawn on the page from the state's `usageAsk` flag; listening is reported by the page with a fixed kind (`usage-listen`); `stock_added` counts stocks however they were added (search, paste, CSV, screenshot); `strategy_saved` says whether it was new or a kept suggestion; `app_open` adds `privacy` (demo mode on) |

Readings: briefing and stock story → `story`, a news TL;DR → `tldr`, a news item's full article → `article` (read only for links in Stockit's news, through `readArticle` so Yahoo's consent page is handled), Flash headlines → `summaries`. Highlighted in place: the briefing card, a stock's story and the TL;DR; the reader (1.1.0, Step 8): a headline's **Read the full article** opens it; items are `"art-" + link` (the Article button's id, so both highlight the same text), found by `byId()` in Stockit's news; the reader's `head(a)` is `rdHead(a)` (Stockit uses `head` as a local name); the reader sits on layer 16, above the news sheet it opens from; the blueprint's `readArticle()` is `readerArticle()`, fetching through Stockit's `articleHTML()` (Yahoo's consent form) with `extractReader()` written on Stockit's `plain()`, while Stockit's older `readArticle()` keeps serving TL;DRs and digests; the setting sits in **News and signals** (Stockit has no Reading section); usage counts `reader_opened` and `article_asked`; Step 9 (getting the page: consent walls, Google News links, Jina Reader, What Stockit tried) was written here first, in 1.19.1–1.19.4, and became the blueprint's `page-fetch.scriptable.js` |
